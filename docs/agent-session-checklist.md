# Agent Session Checklist

Этот чеклист нужен для быстрого и безопасного входа в проект в новой сессии Codex.

## 1. Что открыть по порядку

1. `AGENTS.md` - актуальные правила и ограничения.
2. `docs/README.md` - карта документации.
3. `README.md` - контекст и быстрый запуск.
4. `AGENT_HANDOFF.md` - цель и текущее состояние между сессиями.
5. `CURRENT_VERSION.md` - что считается реализованным сейчас.

## 2. Какие команды безопасно запускать в начале

- `git status --short` - понять текущее состояние изменений.
- `docker compose ps` - проверить статус сервисов без изменения данных.
- `rg --files docs` - быстро увидеть документацию проекта.

Команды, меняющие состояние (например `docker compose up/down`, миграции, массовые правки), выполнять только после подтвержденного плана шага.

## 3. Как понять, что контекст собран

Контекст считается собранным, если агент может коротко ответить на 4 вопроса:

1. Какая цель текущей сессии и критерии успеха?
2. Какие файлы/модули затрагиваются?
3. Какие риски регрессий или инцидентов есть сейчас?
4. Какие проверки нужно выполнить до завершения работы?

## 4. Когда эскалировать вопрос пользователю

Эскалировать нужно сразу, если:

- есть неоднозначность, которая меняет архитектурное решение;
- требуется destructive-операция или риск потери данных;
- нужно изменить `.env`, секреты или внешний интеграционный контракт;
- обнаружены неожиданные чужие правки в тех же файлах, где агент планирует изменения.

## 5. Мини-шаблон первого сообщения в новой сессии

1. Подтвердить цель пользователя своими словами.
2. Назвать первый безопасный шаг (что будет проверено сначала).
3. Сообщить, какие проверки будут выполнены после изменений.
