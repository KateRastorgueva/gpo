## Решение

Катин бот из `C:\Users\abUser\PycharmProjects\Chat-bot` / `https://github.com/KateRastorgueva/Chat-bot` не подключается к проекту как отдельный Telegram/runtime-бот.

Его код рассматривается как прототип и донор идей для отдельного агрегатора веб-источников. Основная система ответов остается в текущем backend проекта и работает по маршруту:

`FAQ -> RAG -> Operator`

## Роль агрегатора

Агрегатор должен собирать и подготавливать источники знаний для backend:

- собирать URL и тексты с официальных страниц ТУСУР;
- собирать URL и тексты с доверенных внешних сайтов, если они нужны для справочных ответов;
- очищать страницы от навигации, футеров, скриптов и прочего шума;
- сохранять результат в JSON/seed-формате, совместимом с `scripts/import-tusur-sources.ps1`;
- не отвечать пользователю напрямую.

## Интеграция с текущим проектом

Подготовленные агрегатором данные загружаются в основной backend через существующий admin endpoint:

`POST /api/v1/admin/sources/upload-json`

Дальше текущий backend:

- сохраняет источник как `KnowledgeSource`;
- индексирует текст в Qdrant;
- использует источник в RAG-ответах;
- возвращает пользователю ответ через единый support pipeline;
- при недостатке контекста передает обращение оператору.

## Что не переносить из Катиного бота

В основной проект не нужно переносить:

- отдельный Telegram/runtime-бот;
- отдельную FAQ-логику;
- SQLite-базу;
- Chroma/vector_db;
- отдельный OpenRouter/OpenAI pipeline;
- отдельный operator pipeline.

Эти части дублируют текущую архитектуру проекта и увеличивают риск расхождения данных.

## Что можно переиспользовать

Из Катиного бота можно взять:

- список страниц ТУСУР;
- список доверенных внешних источников;
- идею поиска по тематическим URL;
- простую очистку HTML через BeautifulSoup;
- примеры пользовательских вопросов;
- формат ответа как референс для будущих улучшений RAG.

## Безопасность

OpenRouter key из `Chat-bot/console_bot.py` считается скомпрометированным, потому что он хранится в коде.

Нужно:

- удалить ключ из кода;
- перевыпустить/отозвать ключ в кабинете OpenRouter;
- хранить новые ключи только через переменные окружения;
- не коммитить секреты, локальные SQLite/Chroma базы и содержимое `vector_db/`.

## Критерии готовности будущей реализации

Агрегатор считается полезным, если он:

- генерирует валидный seed JSON;
- импортируется через `scripts/import-tusur-sources.ps1`;
- создает источники в `/admin-support`;
- позволяет получить RAG-ответы на вопросы про расписание, поступление, стипендии, оплату и контакты;
- сохраняет ссылки на исходные страницы в `sources`.
