# Фильтр офтопа

Вопрос не по теме университета получает вежливый отказ вместо передачи оператору.
В журнал и очередь оператора такой отказ **не пишется**; под ответом у пользователя
кнопка «Передать оператору» (`POST /support/escalate`) — по ней вопрос попадает в очередь как обычный.

**По умолчанию выключен.** Переключатель и пороги — «Управление → Настройки → Фильтр офтопа»
(таблица `app_setting`, не `.env`; `.env` задаёт только значения по умолчанию).

## Как решается

Порядок в `run_support_pipeline`: FAQ → правила мусора → движок/поиск → проверка сходства → прежняя маршрутизация.
Попадание в FAQ (порог 0.90) фильтр не трогает.

1. **Правила мусора** (`offtopic.junk_rule`), для любого движка и без модели:
   нет букв («12345 ???», эмодзи); одна повторяющаяся буква («ааааа»); русский текст в латинской
   раскладке («ghbdtn» → «привет», проверяется по списку корней типичных студенческих вопросов).
2. **Среднее сходство top-N** (`OFFTOPIC_MIN_MEAN_SIMILARITY`, по умолчанию **0.30**, `OFFTOPIC_TOP_N` = 5):
   среднее сырых косинусов (rubert-mini-frida) лучших документов к вопросу. Строго ниже порога — отказ.
   Нужна включённая векторная добавка (`DENSE_SEARCH_ENABLED`) и встроенный поиск (legacy / search_only);
   у Gemini File Search и AnythingLLM наших косинусов нет, там действуют только правила мусора.
   Без косинусов (добавка выключена, кэш векторов пуст) проверка пропускается и работает прежняя маршрутизация.

Отказ пишется в журнал событий (`support.reject`: причина, среднее сходство, порог) — по этим записям
порог подбирают на хосте.

## Ответ API

`POST /support/ask` при отказе: `mode: "reject"`, `request_id: null`, `escalated: false`,
`route_reason` ∈ `junk_empty | junk_repeat | junk_layout | offtopic_low_similarity`, в `answer` — текст отказа.
Отказ в чате живёт только в памяти страницы (после перезагрузки исчезает, как и положено записи, которой нет в базе).

## Замеры

Цифры получены в лабе на ноутбуке (набор 128 вопросов, 49 документов ТУСУР, dense rubert-mini-frida без RRF);
в облачном окружении этого PR набор и модель недоступны, поэтому здесь не пересчитывались:

| | без фильтра | с фильтром |
|---|---|---|
| офтоп ушёл оператору | 48 из 49 | 3 из 49 |
| вопросы по теме, получившие отказ (из 20) | — | 4 |

Цена — около 4 из 20 вопросов по теме получают отказ (кнопка «Передать оператору» это смягчает).
Правила мусора в этом PR написаны заново по описанию (`_local/lab/e8_policies.py` в репозиторий не входит),
поэтому на лабовом наборе их стоит перемерить: `python scripts/eval_search.py` с включённым фильтром.
