# Техническая документация проекта (черновик)

Дата: 2026-03-30  
Статус: Draft v0.1 (AS-IS + GAP + TO-BE шаблон)

## 1. Цель документа
Документ фиксирует текущее техническое состояние проекта, степень готовности, разрыв между текущей реализацией и целевым состоянием, а также базовый план доработки.

Этот документ намеренно сделан как рабочий черновик для дальнейшего редактирования под фактические бизнес-требования.

## 2. Обзор системы (AS-IS)
Проект представляет собой монорепозиторий с веб-платформой на FastAPI + React и инфраструктурой Docker/CI. Также в репозиторий добавлен Telegram-бот как отдельный сервис, но его бизнес-логика почти не реализована.

### 2.1 Подсистемы
- Backend: FastAPI, SQLModel, Alembic, PostgreSQL, JWT auth, email recovery.
- Frontend: React 19, Vite, TanStack Router/Query, Tailwind/shadcn.
- Bot: Python-сервис с Docker-образом и зависимостями, но без полноценной рабочей логики.
- Infra: Docker Compose, Traefik, Adminer, Mailcatcher.
- CI/CD: GitHub Actions для тестов, pre-commit проверок, staging/production deploy.

### 2.2 Примерная оценка готовности (по коду)
- Backend API: 80%
- Frontend кабинет: 75%
- Тесты и CI/CD: 75%
- DevOps/deploy контур: 70%
- Telegram-бот: 10%
- Общая готовность: 65%

## 3. Реализовано сейчас

### 3.1 Backend
- Аутентификация и авторизация на JWT.
- Роли пользователя (обычный пользователь / superuser).
- CRUD для пользователей и items.
- Восстановление пароля по email.
- Health-check endpoint.
- Миграции БД через Alembic.
- Инициализация суперпользователя при старте.

### 3.2 Frontend
- Экраны: login, signup, recover/reset password, dashboard, items, admin, settings.
- Маршрутизация и защита закрытых роутов.
- Интеграция с backend через автогенерируемый OpenAPI-клиент.
- Базовая админка управления пользователями.
- Темизация (включая dark mode).

### 3.3 Качество и процессы
- Backend тесты (pytest + coverage).
- E2E тесты фронтенда (Playwright).
- Автоматические проверки форматирования и линтинга в CI.
- Базовые workflow для деплоя в staging и production.

## 4. GAP-анализ (что не хватает)

### 4.1 Критичный разрыв
- Telegram-бот не доведен до рабочего состояния.
- Логика бота и обработчики команд не реализованы в достаточном объеме.
- Реальных сценариев взаимодействия бота с backend/API пока нет.

### 4.2 Продуктовый разрыв
- Текущая функциональность в основном соответствует шаблону full-stack template.
- Доменные бизнес-сценарии проекта (специфичные для вашей задачи) пока не описаны и не реализованы полностью.

### 4.3 Операционный разрыв
- Нет формализованного production runbook.
- Не зафиксированы SLO/SLA и алертинг.
- Не описаны регулярные процедуры backup/restore.

## 5. Риски
- Риск несоответствия ожиданий: проект воспринимается как готовый продукт, но часть функциональности сейчас шаблонная.
- Риск по срокам: приоритетная доработка бота может потребовать переработки API-контрактов.
- Риск эксплуатации: без формализованных регламентов поддержки сложнее сопровождать прод.
